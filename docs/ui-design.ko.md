# CAE Agent UI 정보 구조와 디자인 시스템

이 문서는 CAE Agent UI v0.2의 화면 구조, 시각 언어와 안전한 상호작용 원칙을
정의합니다. 새 기능을 추가할 때는 개별 화면을 임의로 꾸미기보다 이 기준을
재사용해야 합니다.

## 사용자 작업 순서

UI는 다음 순서를 기본 사용자 여정으로 사용합니다.

1. Python, Codex와 Ansys 환경 상태를 확인합니다.
2. CAE 원본 파일을 `workspace/input`에 업로드합니다.
3. Codex에 원하는 모델링 또는 해석 작업을 자연어로 요청합니다.
4. Codex가 제시한 계획, 스크립트와 예상 변경을 검토합니다.
5. 모델 변경, 해석 실행과 파일 삭제처럼 영향이 있는 작업만 승인합니다.
6. 진행 로그와 결과 파일을 확인합니다.

현재 #41 단계는 환경 확인, 입력 파일, 로그·결과와 유지관리 화면을 제공합니다.
Codex 채팅, 파일 첨부와 작업 승인 카드는 후속 UI v0.2 이슈에서 연결합니다.

## 화면 구조

### 상단 상태 바

- 제품 이름과 현재 작업공간 성격을 표시합니다.
- `LOCAL ONLY` 배지로 외부에 공개되지 않은 서버임을 알립니다.
- 현재 UI 버전을 표시합니다.

### 왼쪽 내비게이션

- `개요`: 환경, 세션, 작업공간과 다음 행동
- `입력 파일`: 안전한 업로드와 최근 원본 파일
- `로그와 결과`: 최근 실행 기록과 CAE 결과
- `유지관리`: 오래된 임시 파일의 미리보기 및 삭제 승인

채팅 기능이 아직 연결되지 않은 동안에는 기능이 있는 것처럼 빈 입력창을
노출하지 않습니다. 대신 로드맵 단계임을 명확하게 표시합니다.

### 개요

사용자가 첫 방문 후 다음 행동을 찾는 화면입니다. 입력 파일 업로드를 주요
버튼으로 제공하고, 환경 검사 결과, 경고 수, 작업공간 용량과 최근 입력 파일
수를 같은 계층의 카드로 표시합니다.

## 디자인 토큰

화면은 어두운 엔지니어링 작업공간을 기본으로 사용합니다.

| 역할 | 값 | 용도 |
| --- | --- | --- |
| 배경 | `#08111f` | 전체 작업공간 |
| 표면 | `#0d1a2b` | 카드와 패널 |
| 강조 표면 | `#122238` | 주요 카드 |
| 기본 강조 | `#38bdf8` | 선택 상태와 주요 행동 |
| 성공 | `#34d399` | 정상 환경과 완료 |
| 주의 | `#f59e0b` | 확인이 필요한 상태 |
| 위험 | `#fb7185` | 실패와 삭제 승인 |
| 보조 텍스트 | `#8fa5bf` | 설명과 메타데이터 |

카드는 18px 모서리와 옅은 테두리를 사용하고, 화면 너비가 900px 이하가 되면
여백과 제목 크기를 줄입니다. 작은 화면에서는 왼쪽 내비게이션을 기본으로
접고 상단 메뉴 버튼으로 열며, 요약 카드는 한 열로 배치합니다.

## 상태와 접근성

- 정상, 주의와 실패는 색상만으로 구분하지 않습니다.
- 상태마다 `PASS`, `WARN`, `FAIL` 텍스트와 아이콘을 함께 표시합니다.
- 버튼에는 행동을 설명하는 동사와 아이콘을 같이 사용합니다.
- 빈 파일 목록은 빈 공간으로 두지 않고 현재 상태와 다음 행동을 안내합니다.
- 긴 파일명은 화면을 밀어내지 않도록 한 줄에서 줄임 표시합니다.

## 안전한 상호작용

- 화면 조회와 새로고침은 Ansys 모델을 변경하지 않습니다.
- 업로드는 `workspace/input`에 새 파일만 생성하며 기존 파일을 덮어쓰지 않습니다.
- 업로드 직후 Workbench, SpaceClaim 또는 Mechanical을 자동 실행하지 않습니다.
- 유지관리 화면은 dry-run을 먼저 실행하고 별도 삭제 승인 대화상자를 사용합니다.
- 삭제 승인 직전에 후보가 바뀌면 이전 승인을 무효화합니다.
- `workspace/input`과 `workspace/results`는 자동 정리 대상이 아닙니다.

## 후속 화면 확장 규칙

채팅, Codex 이벤트와 실행 승인 화면도 같은 내비게이션, 디자인 토큰과 상태
표현을 사용해야 합니다. 서비스 계층은 NiceGUI 구성요소와 분리하고, UI 버튼이
기존 CLI의 승인 경계를 우회하지 않도록 서버에서 다시 검증해야 합니다.
