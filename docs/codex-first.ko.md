# Codex를 사용자 인터페이스로 사용하는 방법

이 문서는 PowerShell 명령을 하나씩 입력하는 대신 Codex에 자연어로 요청해
CAE Agent를 사용하는 경로를 설명합니다. PowerShell은 Codex가 CAE Agent와
Ansys를 제어할 때 사용하는 내부 실행 수단입니다.

## 전체 구조

```text
사용자 자연어
  → Codex
  → CAE Agent CLI
  → Workbench
  → SpaceClaim 또는 Mechanical
```

저장소의 `AGENTS.md`와 `.agents/skills/cae-agent`는 Codex에 설치 순서,
명령 조합, V261 API 규칙과 실행 승인 경계를 알려줍니다.

## 1. 처음 한 번만 준비하기

새 폴더에서 저장소를 받은 뒤 해당 폴더를 Codex에서 엽니다.

```powershell
git clone https://github.com/minwoorich/cae-agent.git
cd cae-agent
codex
```

VS Code 또는 다른 Codex 인터페이스를 사용한다면 저장소 폴더를 열고 새
대화를 시작하면 됩니다. 이후 다음과 같이 요청합니다.

> 이 저장소의 CAE Agent를 처음 사용하는 사용자처럼 준비해줘. 기존 파일은
> 덮어쓰지 말고 설치 계획을 먼저 설명해줘. 준비가 끝나면 doctor를 실행하고
> Python, Codex와 Ansys 상태를 한국어로 요약해줘.

설치 스크립트는 Python, Codex CLI와 Ansys 자체를 자동으로 설치하지 않습니다.
필수 프로그램이 없으면 Codex가 누락된 기능과 별도 설치 필요성을 설명해야 합니다.

## 2. 새 CAE 프로젝트 만들기

> Ansys Workbench를 시작하고 새 Steady-State Thermal 프로젝트를 만들어줘.
> 프로젝트 이름은 `user_test`로 하고 기존 프로젝트는 덮어쓰지 마. 실행 전에
> 생성할 파일과 사용할 시스템 이름을 알려줘.

Codex는 먼저 기존 Workbench 상태를 확인하고, 필요한 경우 장시간 유지되는
Workbench 브리지를 별도 프로세스로 시작해야 합니다. 같은 포트에 세션을
중복으로 시작하면 안 됩니다.

## 3. 자연어로 형상 만들기

> SYS 시스템의 SpaceClaim에 가로 60 mm, 세로 40 mm, 높이 3 mm인 독립
> 직육면체를 만들어줘. 바디 이름은 `Substrate`로 해줘. 자세한 한국어 주석이
> 있는 스크립트를 새 파일로 작성하고, 실행 전에 변경 내용을 보여줘.

Codex는 SpaceClaim V261용 스크립트를 직접 작성합니다. 사용자가 내용을
확인하고 실행을 승인하면 CAE Agent의 SpaceClaim 실행기로 전달합니다.
기존 형상을 지우는 `--clear`는 별도 승인이 없으면 사용하지 않습니다.

## 4. Mechanical로 이어서 작업하기

> 방금 만든 SYS 시스템을 Mechanical에 연결하고 현재 모델 상태를 확인해줘.
> 아직 재료, 경계조건과 열원을 추가하지 마.

이후 공학적 조건을 단계적으로 요청할 수 있습니다.

> 바디 목록을 확인하고 재료 할당 계획을 먼저 제안해줘. 재료 물성은 추측하지
> 말고 내가 제공하지 않은 값은 질문해줘.

> 바닥면 온도를 25 °C로 고정하고 상단에 10 W 열원을 적용하는 Mechanical
> 스크립트를 작성해줘. 선택할 면과 단위, 기존 모델에 미치는 영향을 설명하고
> 내 승인을 받은 다음 실행해줘.

## 5. 실패했을 때

> 방금 실패한 CAE 작업의 traceback과 보존된 스크립트를 확인해 원인을
> 설명해줘. 실패한 파일은 덮어쓰지 말고 수정본을 새 파일로 만든 뒤, 재실행
> 전에 수정 차이를 보여줘.

Codex는 경로와 비밀정보를 가리고, 설정된 최대 재시도 횟수 안에서만 수정해야
합니다. 모델 초기화나 기존 결과 삭제가 필요하면 다시 승인을 요청해야 합니다.

## 최상위 Codex와 `run-agent`의 차이

일반 사용에서는 현재 대화 중인 Codex가 스크립트를 직접 작성하고 CAE Agent
실행기를 사용합니다.

```text
사용자 → 현재 Codex → spaceclaim run 또는 mechanical run-script
```

`cae-agent run-agent`는 내부에서 별도의 Codex CLI 프로세스를 호출합니다.
따라서 다음처럼 어댑터 자체를 시험할 때만 자연어로 명시적으로 요청하세요.

> CAE Agent의 내장 `run-agent` 자동 수정 기능 자체를 시험하고 싶어. 새 테스트
> 프로젝트에서만 실행하고, `--approve-execution`을 사용하기 전에 생성 코드와
> 재시도 횟수를 보여줘.

## 사용자가 직접 승인해야 하는 작업

- AI가 작성하거나 수정한 스크립트의 첫 Ansys 실행
- 기존 SpaceClaim 형상을 모두 지우는 작업
- 기존 Workbench 프로젝트나 연결 데이터를 덮어쓰는 작업
- 기존 재료, 경계조건 또는 해석 결과 변경
- 실제 해석 실행과 라이선스·계산 자원 사용

단순 설치 상태 확인, 설정 조회와 세션 상태 조회는 모델을 변경하지 않습니다.

## 자연어로 작업공간 정리하기

먼저 삭제 없이 사용량과 후보만 확인하도록 요청합니다.

> 작업공간의 폴더별 용량을 확인하고 30일이 지난 정리 후보를 dry-run으로
> 보여줘. 원본 입력과 해석 결과는 제외하고 아직 삭제하지 마.

Codex가 후보 수, 전체 용량, 보존 기간과 건너뛴 링크를 설명한 뒤 실제 삭제가
필요하면 별도로 승인합니다.

> 방금 보여준 안전한 후보만 삭제하는 것을 승인할게. input과 results는
> 그대로 보존하고, 완료 후 감사 로그와 삭제 실패 내역을 알려줘.

실행 중인 세션 정보가 발견되면 Codex는 강제로 정리하지 않고 Workbench와
Mechanical의 정상 종료 상태부터 확인해야 합니다.

## 상태와 승인을 대시보드에서 확인하기

NiceGUI 선택 의존성을 설치한 사용자는 Codex에 다음처럼 요청할 수 있습니다.

> CAE Agent 로컬 대시보드를 시작해줘. 외부 네트워크에는 공개하지 말고
> 기본 브라우저에서 환경, 세션과 작업공간 상태를 보여줘.

Codex는 `cae-agent ui`를 실행하고 UI가 `127.0.0.1`에만 열렸는지 확인해야
합니다. 대시보드는 자연어 대화를 대신하지 않으며 상태 조회, 정리 미리보기와
별도 삭제 승인에 집중합니다. 자세한 내용은 [UI 가이드](ui.ko.md)를 참고하세요.

대시보드에서 STEP, IGES, SpaceClaim, Workbench, Mechanical 또는 표 형식
입력 파일을 올리면 `workspace/input`에 저장됩니다. 업로드만으로 모델을
열거나 해석하지 않으므로, 저장이 끝난 뒤 사용할 파일명과 원하는 작업을
Codex에 자연어로 요청해야 합니다. 같은 이름의 기존 입력은 자동으로
덮어쓰지 않습니다.
