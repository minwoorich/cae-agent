# CAE Agent 로컬 대시보드

CAE Agent UI는 Codex 자연어 인터페이스를 대체하지 않습니다. Codex가 CAE
작업을 조정하는 동안 환경, 세션, 작업공간, 정리 후보와 결과 파일을 한 화면에서
확인하는 localhost 전용 상태·승인 대시보드입니다.

화면의 정보 구조, 색상, 상태 표현과 후속 기능 확장 규칙은
[UI 디자인 시스템](ui-design.ko.md)에 정리되어 있습니다.

## 설치

```powershell
.\setup.ps1 -WithAnsys -WithUI
```

개발 의존성까지 함께 설치하려면 다음을 사용합니다.

```powershell
.\setup.ps1 -WithAnsys -WithUI -WithDev
```

수동 설치도 가능합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[ui]"
```

NiceGUI는 선택 의존성이므로 `.[ui]`를 설치하지 않아도 doctor, Workbench,
SpaceClaim, Mechanical과 Codex-first CLI는 계속 사용할 수 있습니다.

## 실행

```powershell
.\.venv\Scripts\cae-agent.exe ui
```

기본 브라우저가 열리지 않게 하거나 포트를 변경할 수 있습니다.

```powershell
.\.venv\Scripts\cae-agent.exe ui --no-browser --port 8876
```

UI는 항상 `127.0.0.1`에만 바인딩됩니다. 현재 버전은 외부 네트워크 주소를
지정하는 옵션을 제공하지 않습니다.

## 표시 내용

- 왼쪽 내비게이션으로 분리된 개요, 대화, 로그·결과와 유지관리
- 로컬 Codex App Server의 실제 스트리밍 대화
- localhost 전용 실행과 UI 버전을 보여주는 상단 상태 바
- Python, Git, Codex와 Ansys 환경 진단
- Workbench와 Mechanical 세션 메타데이터 존재 여부
- `input`, `generated`, `logs`, `results`, `.runtime`의 파일 수와 용량
- 최근 로그 및 결과 파일 이름
- 채팅 작성기에서 이미지와 CAE 파일 바로 첨부
- 지정 보존 기간보다 오래된 안전한 정리 후보
- 실제 정리 결과, 실패 수와 감사 로그 경로

개요 화면의 `채팅에서 파일 첨부` 버튼을 누르면 대화 화면으로 이동합니다.
`대화` 화면의 서비스 연결 상태에는 Codex와 Workbench가 별도로 표시됩니다.
Codex는 첫 메시지를 전송할 때 localhost 내부에서 `codex app-server`를
시작하며, 별도 API 키를 UI에 입력하지 않고 Codex CLI의 기존 로그인 상태를
사용합니다. `미연결`, `연결 중`, `연결됨` 또는 `연결 오류`로 갱신됩니다.

Workbench는 세션 파일 존재만으로 연결됐다고 표시하지 않습니다. 저장된
localhost 세션 정보로 실제 Workbench에 연결하고 프로젝트 경로를 조회하는
ping이 성공해야만 `Workbench 261 · 연결됨`으로 표시합니다. `연결 상태
새로고침`을 누르면 두 서비스의 상태를 다시 확인할 수 있습니다.

Codex는 기본 읽기 전용 샌드박스에서 시작하지만, 화면에 표시된 정확한 명령 또는
파일 변경 요청 한 건은 사용자가 승인할 수 있습니다. 이 실행 권한은 Workbench
연결 여부와 관계없습니다. 로컬 브라우저를 구분하는 임의 세션 ID는 화면에
표시하지 않습니다.

Codex의 현재 디렉터리는 저장소 소스가 아니라 설정된 사용자 작업공간입니다.
일반 파일 변경은 `workspace/generated`의 작업별 자동화 스크립트에만 허용하며,
설치 소스와 `input`, `results`, `logs`, `.runtime` 변경은 정책으로 거절합니다.
자세한 경계는 [파일 수정 정책](file-policy.ko.md)을 참고하세요.

세션 메타데이터는 연결 가능성을 나타내는 로컬 기록입니다. 실제 Workbench 또는
Mechanical 응답을 보장하지 않으므로 CAE 작업을 시작할 때는 Codex가 기존
`status` 명령으로 연결을 다시 확인해야 합니다.

## Codex 스트리밍 대화

대화 화면은 Codex App Server의 stdio JSONL 프로토콜을 사용해 다음 흐름을
제공합니다.

- 사용자, CAE Agent, 시스템과 오류 메시지의 구분
- 채팅 작성기에서 바로 올린 파일의 자동 분류 첨부 칩
- 응답 텍스트가 여러 조각으로 도착하는 스트리밍 표시
- 공개 reasoning 요약과 명령·파일·도구 작업을 보여주는 접이식 진행 패널
- 응답 중 중복 전송 차단
- 진행 중인 응답 중지
- 마지막 사용자 요청과 첨부 파일로 다시 시도
- 명령, 스크립트와 로그를 위한 접이식 상세 카드

현재 Codex 스레드는 `read-only` 샌드박스와 `on-request` 승인 정책으로
시작됩니다. 상태 확인 같은 일반 명령과 작업공간 파일 변경은 안전 정책으로
자동 승인해 채팅이 중간에 멈추지 않습니다. 자동 승인도 정확한 요청 한 건에만
유효하며 `auto_approved` 이벤트로 감사 로그에 기록됩니다.

SpaceClaim·Mechanical 실행, 해석 solve, Workbench 프로젝트 생성처럼 실제
CAE 모델이나 라이선스 자원을 사용하는 요청과 `--clear`, `--overwrite`, 파일
삭제 같은 복구하기 어려운 작업만 승인 카드를 표시합니다. 광범위 권한, 세션
전체 승인과 레거시 승인 요청은 세부 범위를 안전하게 보여줄 수 없어 자동
거절합니다.
승인 요청과 승인·거절 결과는 `workspace/logs/codex-approvals.jsonl`에
추가 방식으로 기록됩니다.

대화 화면은 채팅 영역이 남은 화면 높이를 사용하고 작성기는 아래에 고정됩니다.
상단의 작은 상태 표시줄에서 Codex 응답 생성 중, Codex 연결, Workbench 연결과
자동 승인 모드를 확인할 수 있습니다. 응답 생성 중에는 회전 표시와
`Codex가 응답을 생성하고 있습니다` 문구가 함께 나타납니다.

작성기에서 `Enter`를 누르면 메시지를 전송하고 `Shift+Enter`를 누르면 줄을
바꿉니다. 한글 입력기의 글자 조합을 확정하는 Enter와 키를 길게 눌러 발생하는
반복 입력은 메시지 전송으로 처리하지 않습니다.

assistant 메시지의 `작업 중` 패널은 App Server가 공개한 reasoning summary와
명령 실행, 파일 변경, MCP 도구, 웹 검색의 시작·완료 상태 및 경과 시간을
표시합니다. 모델의 내부 추론 원문 이벤트는 표시하지 않습니다. 완료 후에는
`작업 과정`으로 접히며 필요할 때 다시 열 수 있습니다.

왼쪽 메뉴로 개요나 로그 화면에 이동하는 것은 같은 브라우저 페이지 안의 화면
전환이므로 채팅 메시지, 진행 상태와 Codex 스트리밍이 유지됩니다. 대화 생성
중에 다른 메뉴를 확인하고 돌아와도 응답은 계속 진행됩니다. 반면 브라우저
새로고침, 탭 닫기 또는 UI 서버 재시작은 브라우저 연결을 종료하므로 현재
메모리 기반 채팅 세션과 Codex 자식 프로세스가 종료됩니다.

Codex CLI가 없으면 설치 안내가, 로그인하지 않았거나 프로세스가 종료되면
상태 확인과 재시도 안내가 채팅 오류 카드에 한국어로 표시됩니다. 다음 메시지를
보내거나 `다시 시도`를 누르면 종료된 연결을 새로 준비합니다.

> 참고: Codex App Server 프로토콜은 실험적이므로 Codex CLI 버전에 따라
> 바뀔 수 있습니다. CAE Agent는 프로토콜 코드를 별도 모듈로 격리해 변경
> 영향을 줄입니다.

## 채팅 파일 첨부

채팅 작성기 왼쪽의 `+` 버튼으로 파일을 선택하면
서버가 파일명, 확장자와 크기를 다시 검증한 뒤 `workspace/input`에 저장합니다.
한 번에 최대 10개, 전체 500 MiB까지 선택할 수 있고 개별 파일은 100 MiB를
넘을 수 없습니다. 브라우저의 파일 선택 제한은 안전 경계로 간주하지 않으며,
서버 검증을 통과하지 못한 파일은 저장하지 않습니다.

지원하는 형식은 다음과 같습니다.

- 일반 이미지: `.png`, `.jpg`, `.jpeg`, `.webp`, `.bmp`
- STEP: `.step`, `.stp`
- IGES: `.iges`, `.igs`
- SpaceClaim: `.scdoc`
- Workbench와 Mechanical: `.wbpj`, `.mechdat`
- 데이터와 작업 설명: `.csv`, `.json`, `.txt`

파일 하나의 최대 크기는 100 MiB입니다. 빈 파일, 실행 파일, 경로가 포함된
파일명과 Windows 예약 이름은 거부합니다. 같은 이름의 일반 입력 파일이 이미
있다면 즉시 덮어쓰지 않고 기존 크기와 새 파일 크기를 보여주는 `기존 입력 파일
교체` 경고 모달을 엽니다.

`기존 파일 유지`를 누르면 새 업로드를 버리고 원본을 변경하지 않습니다. `파일
교체 승인`을 누르면 모달을 연 뒤 기존 파일의 크기 또는 수정 시각이 바뀌지
않았는지 다시 검사한 다음 같은 이름의 파일만 원자적으로 교체합니다. 상태가
달라졌거나 심볼릭 링크이면 승인을 무효화합니다. 교체 기록은
`workspace/logs/upload-replacements.jsonl`에 추가됩니다.

사용자는 이미지나 CAE 모델 같은 종류를 직접 선택하지 않습니다. 확장자에 따라
`이미지`, `CAD/형상`, `Ansys 모델`, `데이터/문서`로 자동 분류해 첨부 칩에
표시합니다. 이미지는 Codex 이미지 입력으로 전달하고, 나머지 파일은 분류와
안전한 로컬 경로를 전달합니다. 전송이 끝나면 작성기의 선택은 비우지만 `다시
시도`에는 원래 메시지의 첨부 파일을 그대로 사용합니다.

업로드와 첨부 선택은 파일 보관과 작업 대상 준비만 수행합니다. SpaceClaim
가져오기, Workbench 프로젝트 열기 또는 Mechanical 해석을 자동으로 시작하지
않습니다. 파일과 함께 Codex에 다음처럼 요청하세요.

> 방금 업로드한 `package.step`을 검토하고 SpaceClaim에서 가져오기 전에
> 변경될 내용을 설명해줘.

## 정리 승인

`정리 후보 미리보기`는 `workspace clean`의 dry-run만 실행합니다. 이 단계에서는
파일을 삭제하지 않습니다. 후보가 있는 경우에만 별도 확인 대화상자가 열리며,
`삭제 승인` 버튼을 눌러야 실제 정리가 실행됩니다.

자동 정리 대상은 오래된 `generated`, `logs`, `.runtime/codex` 파일로
제한됩니다. 다음 항목은 UI에서도 자동 삭제할 수 없습니다.

- `workspace/input`
- `workspace/results`
- Workbench와 Mechanical runtime
- 심볼릭 링크
- 작업공간 밖으로 해석되는 경로

실행 중이거나 종료가 확인되지 않은 세션 메타데이터가 있으면 실제 정리가
차단됩니다. 세션 파일을 강제로 삭제하지 말고 Workbench와 Mechanical을 정상
종료한 뒤 다시 확인하세요.

## 현재 범위

현재 UI는 읽기 중심 대시보드, 채팅 첨부 보관과 실제 Codex 대화 기능을 제공합니다.
SpaceClaim 형상 생성, Mechanical 경계조건 변경과 해석 실행 버튼은 제공하지
않습니다. 모델 변경과 자연어 작업은 Codex를 통해 진행하고, 기존 Skill의 실행
승인 규칙을 그대로 적용합니다.
